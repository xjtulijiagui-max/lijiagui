用户故事

你是海岳银行分行零售运营经理

本周需要把三家支行的聚合经营周报，转成可执行的网点行动。问题是：文件字段不统一，其中一份周次不一致，还有一条记录缺少责任人。你不能跳过这些问题，也不能让 AI 猜测补齐。

最终交付不是一份孤立报告，而是一条能重复运行的闭环：资料先通过质量闸门，再形成 IPO、九步 SOP，最后封装为可测试的 Skill。

教学模拟声明 页面中的银行、网点、人员、客群与金额均为虚构聚合数据，不代表真实银行业务。练习不涉及个人级客户信息，也不替代授信、适当性、风险或合规判断。

任务 01 提示词工作空间只读盘点与数据质量检查
# 角色
你是海岳银行分行零售运营经理的数据质量助手。

# 任务背景
我需要汇总 2026-W32 三家支行的聚合经营周报，但文件字段不统一，且可能存在周次、责任人、口径或敏感数据问题。所有资料均为教学模拟。

# 输入资料
请读取当前工作空间中的：
1. 《01_支行周报字段字典.md》
2. 三家支行周报 CSV
3. 《05_零售业务数据边界.md》
4. 《06_活动与服务资源.csv》

# 任务目标
在不修改任何源文件的前提下，生成资料资产地图、字段映射表和数据质量报告，并判断能否进入下一步汇总。

# 处理要求
1. 先列出全部文件、用途、格式、数据责任人和是否齐套。
2. 按字段字典映射不同列名，同时保留原字段名与来源文件。
3. 检查必填字段、周次、单位、空值、重复、日期和“可经营 ≥ 已联系 ≥ 预约 / 有效沟通”的数量关系。
4. 检查是否出现个人姓名、完整手机号、证件号、银行卡号、精确地址或其他不应进入练习的敏感数据。
5. 每个问题都写明证据：文件名、行号或记录定位、违反的规则、影响范围。
6. 将问题分为“阻断项”和“非阻断项”。存在阻断项时停止，不汇总、不改源文件。
7. 对需要人工判断的内容，只生成待确认问题，并标注应由运营、网点负责人或风险人员中的谁确认。

# 输出要求
依次输出：
A. 资料资产地图
B. 字段映射表
C. 数据质量报告
D. 阻断项与非阻断项清单
E. 待确认问题
F. 是否允许进入任务 02 的结论与理由

# 边界
本轮只读。未经确认不得移动、改名、删除、覆盖或上传文件；不得推断敏感属性，不得给出授信、购买、适当性或客户风险结论。

任务 02 提示词Plan 模式下完成 IPO 与九步 SOP
# 角色
你是海岳银行分行零售运营流程设计顾问，负责把已确认的聚合周报处理要求转成可复核的业务流程。

# 任务背景
任务 01 已完成只读盘点。请读取我上传的任务 02 资料，以及我提供的任务 01 质量报告（如有）。所有资料均为教学模拟。

# 第一阶段：只制定计划，不执行
请先在 Plan 模式输出：
1. 输入文件与口径依赖
2. 处理阶段与先后关系
3. 需要使用的 WorkBuddy 能力
4. 数据质量、业务策略、风险复核三个强制关卡
5. 每阶段产物、责任角色、验收人和失败回退
6. 仍需我决策的问题

输出计划后停止，等待我回复“确认执行”。

# 第二阶段：收到“确认执行”后再执行
1. 按《01_IPO工作表.md》梳理“支行存量客户经营周闭环”的 Input、Process、Output。
2. Input 必须写明文件、字段、来源角色、频率、敏感等级、必需/可选、质量标准和缺失处理。
3. Process 必须写明规则、WorkBuddy 能力、责任角色、前置条件、异常分支、人工决策点和过程记录。
4. Output 必须写明使用者、格式、字段、频率、复核人、质量标准和下游动作。
5. 按《02_九步SOP模板.md》生成九步 SOP：建任务、校验数据、统一口径、形成客群、识别机会、匹配动作、生成材料、风险复核、回收结果。
6. 每一步写清责任角色、输入、具体动作、WorkBuddy 能力、输出、质量闸门、异常处理和预计时长。
7. 用“缺报、字段冲突、敏感信息、无证据机会”四类异常做桌面演练，写明在哪个闸门停止、由谁确认、保留什么记录。

# 输出要求
A. 已确认口径与版本
B. IPO 工作表
C. 九步 SOP
D. 四类异常桌面演练
E. 待确认问题与责任角色

# 边界
不得新增材料中没有依据的流程；不得把相关性写成因果；不得自动生成客户名单或自动触达客户；AI 只产出内部草稿，所有对客动作、业务策略和风险判断由人工确认。

  2. 在 WorkBuddy 中唤起 Skill Creator
  3. 复制提示词，创建并检查 Skill 目录与边界

任务 03 提示词Skill Creator 封装、测试与版本边界
# 角色
你是 Skill Creator。请把《01_存量客户经营周闭环SOP_v1.md》封装为“存量客户经营周闭环”Skill。

# 任务背景
这个 Skill 用于处理海岳银行三家支行的脱敏聚合经营周报。它必须先校验，再分析；必须保留人工关卡；错误样本的正确行为是停止。所有资料均为教学模拟。

# 输入资料
请读取：
1. 《01_存量客户经营周闭环SOP_v1.md》
2. 《02_Skill输入输出规格.md》
3. 《03_测试样本集.csv》
4. 《04_测试记录模板.csv》

# 创建要求
1. 触发语：生成周行动、复盘存量客户、制作网点经营作战包。
2. 必需输入：00_规则、01_输入、02_过程、03_模板；缺一类先报错。
3. 严格按 SOP 九步运行，每个质量闸门通过后才能进入下一步，并保存中间检查记录。
4. 输出质量报告、标准明细、机会清单、行动台账、沟通提纲、风险清单、管理摘要、反馈模板和运行日志。
5. 停止条件必须覆盖：未脱敏信息、文件缺失、字段含义或单位冲突、无规则依据、要求自动联系客户、要求授信或购买结论。
6. 人工确认点必须覆盖：字段映射、更正记录、经营机会、行动台账、对客话术和最终外发。
7. 不得覆盖原文件，不得自动发送、拨打或修改客户标签。

# 测试要求
1. 按《03_测试样本集.csv》运行 3 个正常、2 个边界、4 个错误场景。
2. 每个场景记录输入版本、预期行为、实际行为、到达的质量闸门、是否通过和停止原因。
3. 错误样本只允许输出质量报告与停止日志，不得继续生成行动台账。
4. 如果实际结果与预期不一致，先修正 Skill，再重新运行该场景；保留修正记录。

# 最终输出
A. Skill 目录与文件说明
B. 触发、输入、输出、停止条件与人工确认点清单
C. 9 个场景的测试记录
D. 未通过项、修正记录和剩余风险
E. 版本更新建议

# 版本边界
只提出下一版建议。未经业务负责人和风险人员共同批准，不得把测试中的临时修正直接作为正式业务规则。
