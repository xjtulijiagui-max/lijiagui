03 / 课堂怎么推进

短讲解，把时间留给真实迭代

一天参考排期：净学习6小时，另含20分钟休息；上午9:00—12:00，下午14:00—17:20。

不是固定授课日程。可按场景难度、小组数量与课前试跑情况调整。

时间时长安排与目的
09:00—09:2020分钟开场短讲与对齐看试跑结果，示范一个完整业务闭环。
09:20—10:3070分钟第一轮优化先解决无法启动、导入或执行的阻断问题。
10:30—10:40休息短休息10分钟，不计入净学习时长。
10:40—11:0020分钟按问题补课补讲当前最集中的数据、规则或环境问题。
11:00—12:0060分钟第二轮优化完善输入映射、规则计算与结果校验。
14:00—14:2020分钟按问题补课根据现场需要补讲API、来源追溯与边界。
14:20—15:2060分钟第三轮优化打通输出与异常处理，回归已通过功能。
15:20—15:30休息短休息10分钟，不计入净学习时长。
15:30—16:0030分钟整理最终交付沉淀SOP/Skill、版本与证据，换人复跑。
16:00—17:0060分钟小组路演8组示例：每组5分钟演示+2分钟问答。
17:00—17:2020分钟复盘与下一步总结可复用方法，列明遗留与试点责任。
遇到问题，再补知识

问题就是补课入口

老师先解释方法，学员马上回到本组场景验证，不停留在听懂。

不知道先做什么

补IPO与最小闭环，先收敛任务范围。

输入还是大段JSON

补Excel上传、字段映射、预览校验与批量导入。

计算与解释对不上

先分开固定计算和AI归纳，再核对来源与口径。

接口或检索不可用

分清工具账户、应用运行时API和独立检索接口。

一修改就把旧功能改坏

补版本保存、最小改动和回归验证。

做完却不会交付

补运行说明、SOP/Skill和验收证据。

每轮只改1—3个关键问题。
优先跑通与算对，再优化输出和体验；每次改动都要回归。

05 / 路演与最终交付

不只展示“做了”，还要证明“能用”

用真实执行结果说话。收益未测量就标待验证，功能未完成就列遗留项。

每组7分钟，讲清一个闭环

5分钟演示 + 2分钟问答。8组约60分钟，包含换场；组数变化时应重新安排。

0:00—0:40
业务问题

谁用、何时用、原来怎么做、为什么值得改。

0:40—1:20
IPO与边界

输入、关键规则、输出，及必须由人确认的节点。

1:20—3:20
现场运行

跑一次正常样本，再展示一次异常拦截。

3:20—4:20
迭代证据

说明课前与课堂版本差异，展示修复和回归结果。

4:20—5:00
交付与下一步

入口、模板、流程、验证记录、遗留项与责任角色。

5:00—7:00
问答

如何核验？失败怎么办？换个人能否复跑？

建议评价表 / 100分

看作品与证据，不只看页面

可信、安全与人工边界20分

生产使用还需要数据授权、真实权限、系统集成、安全、测试和运维评审。涉及复杂数据库或业务系统的部分，应移交IT继续推进。

评分仅评价小组作品，不用于个人绩效或人事决定。
