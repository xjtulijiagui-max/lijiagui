任务做成一次，不等于方法能够复用

模块二已经让我们通过 I（输入）—P（处理）—O（输出） 讲清一项业务任务。模块三再用 CHAT 补背景、细化子 IPO、人机接力并按 O 验收。到这里，解决的是“本次任务如何正确交付”。模块四不再重新拆场景，而是解决“以后能否稳定重复交付”。

从“我会让 AI 做一次”，升级为“我和同事下次还能按同一标准做”。

02

IPO 转 SOP：把“这次怎么做”提炼成“每次怎么做”

IPO 是任务结构，SOP 是可重复执行的操作规程。不是让 AI 凭空编一套标准流程，而是从模块二的任务卡和模块三实际跑通、通过验收的动作中，抽取每次不变的操作方式。

I · 输入标准化

哪些文件/字段每次都必备？如何检查时效、权限、口径？缺资料怎么办？

P · 过程步骤化

把“分析处理”变成动作、判据、分工、检查点；复杂 P 可以展开为子 IPO。

O · 输出可验收

固定交付格式、关键字段、引用来源与核对规则，保留人工最终确认点。

异常可回退

遇到缺数据、口径冲突、结果不达标时，暂停、追问、退回哪一步？

一案贯穿｜月度项目跟进汇报

Input

每月提供最新项目台账、会议纪要、风险登记与上期结论；检查完整性与日期。

Process

核对数据 → 比较变化 → 标注风险与证据 → 人工确认争议口径 → 生成汇报初稿。

Output

交付进展摘要、风险及决策事项、责任人和待办；按约定格式和证据标准核验。

这里的“项目跟进”是教学示例，不预设 vivo 的实际系统字段、审批制度或风险阈值。

可复制提示词 A｜从验证记录萃取 SOP可在新对话中使用：上传任务卡和实际执行证据，不依赖原聊天记录自动可见。

03

      
SOP 转 Skill：把“操作规程”封装成“可调用的能力”

      
SOP 告诉人怎么做，Skill 告诉支持该机制的 AI 何时调用、拿什么材料、按什么步骤执行、如何检查结果、失败怎么处理。它不是多写一条万能提示词，更不是把整段聊天复制进去。

    

    

      
IPO · 业务内核→SOP · 稳定流程→Skill · 可调用规则

      

        
Skill 能力包：内容不止一条 Prompt

        

          
SKILL.md
名称与 description、触发条件、完整步骤、输入/输出、检查和边界。文本可编辑。

          
references / assets（按需）
引用已授权的 SOP、字段说明、报告模板、样例输入输出等；避免依赖原会话。

          
scripts（按需）
只有需要可重复计算、校验或集成时，才放脚本；无代码任务并不强求。

        

      

      

        可复制提示词 B｜SOP 封装为 Skill 草稿先得到可审核的 SKILL.md 及引用文件清单；实际加载与运行取决于所用平台。
      

      
展开完整提示词

      
一个容易混淆的边界
在普通对话工具中生成 SKILL.md 草稿，不代表 Skill 已安装、可自动触发或能访问业务系统。需要在支持 Skill 的环境中按平台规则导入、授权、测试，才谈得上运行和共享。
