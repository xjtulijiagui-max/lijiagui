今天只记六句

上午讲“上下文”，下午讲“怎么用好”。复习时先把这六句讲给同事听。

  1. 智能体 = 大脑 + 身体。模型是大脑，工具、连接器、电脑权限是身体。要变成好智能体，必须给足上下文；没把业务知识交给它，它只是“大号的 DeepSeek”。
  2. 上下文（Context）是核心竞争力。提示词交代清角色、背景、目标、行动；一次把话说清楚，最省钱也最出效果。
  3. 人的价值在两头：派活和验收。派活派得对（规划设计），验得出好坏（判断力 + 品味）。小白 + AI，还是小白。
  4. 一个对话一个任务。多任务混聊会成本爆炸、上下文混乱、越聊越笨；长对话要压缩，重要任务第一轮就把资料给全。
  5. 先给 AI 做“入职初始化”。不变的规矩写进个性化，可变的偏好放进记忆，每次纠正都说一句“请写入记忆”。
  6. 复杂任务先 Plan，提示词加护栏。计划五要素：目标、步骤、依赖、改动、验收。四不护栏：不编造、不乱改、不越权、不糊弄。

核心：课尾总结的三组提示词

讲师在课程最后重点演示的内容：给 AI 立规矩、让它记住你的修改、一句话出周报。

P-01

个人背景记忆（讲师原版，供参考改写）

用户使用中文交流，称呼助手为“大哥”，偏好直接、不啰嗦、不客套的回复，先给结论，对低级错误容忍度低，对比其他AI表现时会直接指出；通常以简短祈使句（如“继续”）驱动AI主导工作流，多步骤任务中用单字批准逐步推进。具备丰富的企业AI项目、内训与TTT课程交付经验，重视真实性与深度洞见，强批判性思维，习惯使用分层框架与六维分析。严格禁止编造数据，缺失字段统一标记“待确认”，并明确区分“已有证据”“综合推断”“待核验”；偏好IPO格式、规则引用、证据索引等可追溯交付。原型/PRD任务须先进入Plan模式，说明理解、缺口、步骤与验收标准；执行后须进行格式、事实、边界、可用性四维自检并列出待确认项。设计需求通常提供含广告语、配色、字体、视觉元素等参数的详细结构化简报。倾向要求现成可参考、可直接“抄”的技能与模板，而非从零构建。公众号文章倾向参照现有链接的结构与风格。发生错误时，用户会立即提供新凭据并要求重试；对公众号草稿箱等外部系统执行不可逆写入前，倾向先审核并确认写入目标。

贴在哪：设置 → 记忆与计划 → 编辑记忆；其中永远不变的规矩放进 设置 → 个性化。

讲师提醒：这段是 AI 根据讲师日常任务自动总结出来的，不是手写的。先读懂，再改成你自己的；“大哥”这类称呼、你用不上的风格要求直接删掉，否则它会误解你。读的过程比贴进去更重要。

P-02

学员改写模板：给自己的 AI 做入职初始化

我是【公司/部门】的【岗位】，向【直属领导】汇报，核心考核指标是【KPI/OKR】。
我当前负责的项目：【项目名称、目标、关键节点】。
我每天/每周重复做的重要事项：【事项1】；【事项2】；【事项3】。
我的做事原则：【例：排产计划优先全局最优，只有在……情况下才接受局部最优】。
回复要求：用中文，先给结论，不客套不铺垫；信息不确定不要编，缺失项标“待确认”。
输出偏好：【例：报告默认生成 Word；数据默认 Excel；PPT 一律用我的模板】。

四件事写清楚：定人设（你是谁、老板是谁）、定目标（项目和 KPI）、定做事方式（原则、要调用的技能）、定输出形式（Word、Excel 还是 PPT）。课堂上把这一步叫“人员初始化”。

P-03

把每次修改变成规则：“XX，请写入记忆”

【刚才纠正它的那条要求】，请写入记忆。

例：“开头直接进入具体问题，不要铺垫，请写入记忆。”同一个问题纠正过一次以上，就当场让它写入记忆，下次自动照做。

P-04

一句话生成本周周报

请基于本周的全部上下文，包含私聊、群聊、日程、待办、企业文档、企业会议的全部内容，帮我生成一个本周周报。
P-05

周报直接生成企业微信云文档

请基于本周的全部上下文，包含私聊、群聊、日程、待办、企业文档、企业会议的全部内容，帮我生成一个本周周报，并生成企业微信文档。
P-06

部门负责人：汇总全组周报

请针对这个群里所有人的本周周报，帮我汇总成本周部门规划。

完整流程：生成周报 → 导出或复制 → 用“去AI味”技能润色（见 P-20）→ 通读后提交。人工汇总只能抽样，AI 汇总能覆盖全量。

前提：WorkBuddy 已连接企业微信并获得企业授权。

交之前必须通读。私聊、群聊里对领导的议论会被一起写进周报，课堂上讲过真实翻车案例。周报里不要出现对具体领导的评价；平时在工作群里说话也要有分寸。

P-07

个性化指令示例：角色一致 + 关键词触发技能

我是一名培训咨询顾问，回复要与我的角色保持一致；做 PPT 永远使用我的模板。
当输入包含“课程大纲”或课程大纲制作方案时，先调用课程大纲 skill。

这是讲师自己的两条。第二条是“关键词触发技能”的写法：把“课程大纲”换成你的高频任务，把 skill 换成你已安装的技能。统一模板的好处像统一设备型号，客户需求怎么变都能快速组装。

P-08

干活前先读工作台文档

开始任何任务之前，先读取【文档绝对路径，例：D:/工作台/我的工作台.md】，按其中的身份、目标和规则执行，读完再动手。

文档里写：我是谁、身份定位、长期目标、KPI、做事规则。讲师经验：规则在 300 行以内基本都会遵守。所有任务都先读会拖慢简单任务，可以改成“处理【某类任务】之前先读……”。

一次把话说清

交代越完整，效果越好；一次说清楚，也最省钱。

P-09

完整交代：角色、背景、目标、行动

角色：你是【岗位/专家角色】。
背景：【项目情况、已有材料、读者是谁】。
目标：【要达成什么结果】。
行动：【具体要做什么，输出成 Word / Excel / PPT 的什么样子】。

交代不清，同一个工具效果天差地别。重要任务把第一轮写完整，后面少来回。

P-10

让 AI 按领域权威的思维框架作答

请按【本领域公认的权威专家】的思维框架回答，结合【精益/工艺等方法论】，给出系统性的解决方案。

讲师建议：把你们整理过的方法论（如精益理论）加进去，要求回答有系统性。

P-11

防“彩虹屁”：要求客观中立

请客观中立，基于数据作答，不要夸赞。

初稿写得一般，AI 却说“你真棒”，人很容易在表扬里迷失。写进指令，或直接放进个性化。

P-12

开放任务：先翻本机资料再动手

先在我电脑上找一找有没有与【任务】相关的可用资料，再基于这些资料帮我完成【任务】。

需要打开完全访问里的“文件操作”。讲师经验：本机资料通常比网上资料质量高，它甚至能翻出你忘了的旧文件。涉密资料不要放在它能访问的范围。

Plan 与护栏

让错误发生在执行之前；把“不编造、不乱改、不越权、不糊弄”写进提示词。

P-13

课堂演示：计划模式下提一个复杂问题

锂电设备的装配精度控制，请出一个系统的解决方案。

先打开计划模式再发送。AI 会先反问澄清需求，再查资料出计划；你按五要素评审，不同意就把修改意见告诉它，改成可执行的计划再执行，产物质量会明显提升。

P-14

没开计划模式时：要求先出计划

先不要执行。请按目标、步骤、依赖、改动、验收五项给出计划，我确认后再执行。
P-15

四不护栏

不允许编造、不允许乱改、不允许越权、不允许糊弄。

写进提示词或个性化，可以明显降低幻觉。记笔记只记这四个词就够了。

P-16

清理电脑：先审计，不要急着动手

请帮我审计我电脑上的【文件夹/文件】，请先审计，不要着急干活。

直接说“帮我清理一下电脑”风险很大。审计完你心里有数哪些不能动，再决定清理范围。

电脑与浏览器

打开权限、装好浏览器操控后，AI 可以像人一样操作电脑和网页。

需要打开完全访问里的“终端命令”。能查电池，就能帮你排查电脑底层问题。

P-19

让 AI 替你填系统表单

帮我在【系统/网站名称】里填写【表单/工单】，参照我过去填写的情况把字段都填好；遇到验证码或授权时停下来让我处理，提交前先给我确认。

适合内网系统填单、工单录入、电商上架这类字段多、规则清楚的活。下班前派活，第二天早上验收。

写作与技能

技能入口：专家技能连接器 → 技能 → 搜索，选下载量最大的。Office 三件套（Word、Excel、PPT）的技能最重要。

P-20

去 AI 味：让报告读起来像你写的

请用“去AI味”技能改写这份【周报/报告】：保留全部事实、数字和结论，不新增内容，删掉套话。

先安装技能：搜 humanizer 或“去AI味”，是课上最受欢迎的技能之一。

P-21

数据分析：调用技能，让它写代码算

调用数据分析（Data Analysis）技能：读取【文件名】，用 Python 计算【指标】，输出结果表、图表和计算代码。

先安装：搜“数据分析”或 Data Analysis，选下载量最大的。调用后它会直接写 Python 来算。

P-22

PPT 加大信息浓度

请把 PPT 的信息浓度加大。

讲师的 PPT 都由 AI 制作，常用做法是把 4 页 Word 浓缩成 1 页 PPT。配合技能 PPT Master（搜索时选下载量最大的）。

做专家与做技能

用技能是起点，把自己的方法做成专家和技能，经验才能留下来、给同事复用。

专家三件套：Profile + Capability model + Workflow

专家是一个有统一人设、带着多个技能的 AI 虚拟员工。你只交代目标，它自己调度工具、保持上下文连贯、按统一口径交付。技能是能力级，专家是角色级。

什么时候该做专家：每次做项目都要重复调用好几个技能、反复交代同样的背景；希望不管调哪个技能，输出都是同一个口径和交付标准；工作需要连续的上下文。一个技能就能搞定、或者方法还在验证阶段，先用技能。

三件套写什么避免
Profile
人设档案		短角色名，便于召唤（如“文档评审官”）；是谁 + 什么背景（如“十年经验的采购经理”）；服务谁、说话风格。“专家1”“助手”这类没有指向的名字；把任务本身当人设。
Capability model
能力模型		擅长什么、不做什么，边界写清楚；挂哪些技能、连接器和资料库。“什么都行”。
Workflow
工作流		先做什么、后做什么；输出格式；约束（四不护栏、缺信息标“待确认”）；最好附一个例子。只写一句“你是一个专家”。

创建路径：专家技能连接器 → 专家 → 我的专家 → 创建专家，在引导对话里逐项确认，再用真实任务测试、修改。专家名称创建后不能改，起名前想清楚。

P-23

创建专家：按三件套一次交代

请帮我创建一个专家，名称：【短角色名，如“来料检验评审官”】。
一、人设档案（Profile）：它是【十年经验的××工程师】，服务【谁】，说话风格【先给结论，不客套】。
二、能力模型（Capability model）：擅长【任务1】【任务2】【任务3】；不做【越界事项】；可调用技能【技能名】；参考资料【资料库或 IMA 知识库名称】。
三、工作流（Workflow）：①【澄清需求】→ ②【读取资料】→ ③【分析或生成】→ ④【自检】→ ⑤【按××格式交付】。
约束：不允许编造、不允许乱改、不允许越权、不允许糊弄；缺失信息标“待确认”。
示例：【附一个做得好的样例】。

做技能：IPO → SOP → Skill

技能的本质是流程加知识，它不是一段更长的提示词，而是一套可触发、可执行、可迭代的能力包。三条都满足再动手：常做（每周每月都会遇到）、做法稳定（不是今天一个流程明天一个流程）、有标准好验收（知道什么是对的）。

  1. IPO写给 AI输入、处理、输出说清楚，并已用测试数据验证。未经验证的 IPO，转出来的 SOP 可能有问题。
  2. SOP给人审核一句话转：“把以上内容转成SOP”。有步骤、有规则、有检查，人读着舒服，存成 Markdown 就是个人、部门、公司的资产。
  3. Skill给 AI 执行把 SOP 丢给智能体说“生成××skill”。以后输入“/技能名”，加上新的输入，直接拿结果。

更快的路：一句话转技能。一个任务在对话里跑通了，当场说一句“把刚才的完整流程存成技能”，以后说名字就整套复跑。

怎么检查技能合不合格：先人审 SOP，确保人读得懂、没有漏洞；再用真实输入跑一遍，人审结果。手工做得比技能好，说明技能有问题：先改 SOP，审过后用自然语言改技能。

讲师案例：做课程大纲，从多轮对话约 2 小时，变成调用技能约 20 秒出稿。

P-24

第一步：写 IPO

任务：【岗位上的一件高频重复工作】
输入（I）：【输入文件、字段、来源、质量要求；缺失信息怎么处理】
处理（P）：【执行步骤；判断规则写成“如果……则……，除非……”；异常处理；人工复核点】
输出（O）：【报告或表格结构、必备内容、文件格式；一个合格样例和一个不合格样例】
验收：【三条可检验的验收标准】

自检：随便找一个同事，拿这份 IPO 能不能做出同样的判断？不能，就是规则还没写透。

P-25

第二步：IPO 转 SOP

把以上内容转成SOP。
P-26

第三步：SOP 转 Skill

请把以上内容整理成一个可重复使用的skill，命名为【项目跟进助手】。

通常需要多轮迭代。生成后输入“/项目跟进助手”，再上传本周纪要，直接拿结果。

P-27

一句话转技能：跑通即保存

把刚才的完整流程存成技能，名字叫【月度对账】。写清步骤和输出格式；缺哪个文件就明说，不要自己编数据。

以后只说“月度对账”四个字，整套流程自动跑。

P-28

迭代技能：改好 SOP 再改技能

SOP 第【3】步已更新为【新的做法】，请按更新后的 SOP 修改【技能名】技能，其余部分保持不变。

知识点复习

按课堂顺序整理，点开看要点。打印时会自动全部展开。

1. 智能体和大模型差在哪
  • 大模型是大脑，智能体是大脑加身体。DeepSeek、豆包本质是大模型；WorkBuddy、豆包工作、千问办公是桌面智能体。
  • 除模型以外的工具、连接器、电脑权限都算“身体”，而且还在长；大脑（模型）可以换。
  • 过去只能问答聊天；现在能完成复杂任务、调用工具、像人一样直接操作电脑。
  • 没受过教育的智能体和受过教育的智能体，差别不亚于原始人和名校博士，关键在给足上下文。
2. 上下文从哪里来
  • 以前三种：提示词、上传附件、允许联网搜索。
  • 现在多了：本地文件、连接器、整台电脑和电脑上的软件、微信和企业微信、资料库、腾讯文档、IMA 知识库。
  • 好提示词要交代角色、背景、目标、行动；交代不清，同一个工具效果天差地别。
  • 技巧都是杠杆，真正决定上限的是专家知识。知识库就是给 AI 的参考答案和“小抄”，拿掉它水平立刻掉下来。
  • 人要有判断力（识别幻觉和噪音）和品味（知道做好一件事的最佳流程和标准）。
3. 微信与企业微信变成上下文
  • 微信聊天记录三步导入：多选后合并转发 → 选择“其他应用” → 选 WorkBuddy 打开。讲师实测单次最多 99 条。
  • 企业微信打通后，群聊、单聊、会议、日程都能成为上下文，需要企业审批开通权限。
  • AI 会抓取并总结聊天记录，工作群里说话要有分寸。
4. 记忆：个性化与记忆的分工
  • 大模型只在当前对话里记事，上下文太长就会遗忘、变笨，多问几次也不会变聪明。WorkBuddy 用“外置记忆”补上，像给电脑加了块移动硬盘。
  • 个性化是常设的、不变的规矩；记忆是可变的、会自动迭代的偏好。永远不许变的放个性化，临时的放记忆。
  • 让 AI 越用越懂你的三个条件：写下自定义规矩；给它一个固定工作区（一类工作一个空间，不来回换）；把每次修改变成规则（P-03）。
  • 记忆别写太泛，“管天管地”的规则会让简单任务也去读，反而变慢。会记，也要会删。
  • 工作电脑上不聊炒股、情感等私事，会搅乱记忆、拉低效率。
  • 记忆文件在用户目录下 .workbuddy 隐藏文件夹里的 memory 文件，前端看到的就是它。
5. 一个对话一个任务
  • 多个任务混在一个对话里有三个坏处：成本爆炸（第 20 轮的消耗约为第 1 轮的 11 倍）、上下文混乱、超出上下文窗口后明显变笨。
  • 长对话在输入框输入“/”，选压缩命令即可压缩（课堂演示从 12.5% 压到 3.3%）。
  • 设置 → 智能体 → 经济模式：自动压缩，讲师估计能省一半左右，但复杂任务会变笨。
  • 重要任务（升职加薪、关系重大、保密要求高）关掉经济模式；第一轮把资料给全，减少轮次；必要时先开一个对话专门整理和清洗上下文。
  • 先辅助跑通三次，再沉淀成固定模板。
6. 省钱习惯
  • 直接让 AI 生成文件，不要在对话框里刷长文。
  • 同类任务批量提交：改 1 个文件名和改 1000 个，消耗几乎一样。
  • 一次把话说清楚，最值钱也最省钱。
  • 简单问答先在免费工具里聊清楚；按任务选模型，小任务不用贵模型。
  • 官方每天可领 100 积分，不领一定不够用。
  • 算时间账：按月薪一万一估算，一分钟约 1 元，别为省 0.5 分钱花一分钟切换工具。
7. 选模型与自购 API
  • 不用 Auto 和“快 / 中 / 高”几个自动档；讲师只按“简单 / 中度 / 重要”三档手动选。
  • 重要任务直接选最贵的；简单任务 10–20 分钟还搞不定，不要犹豫，直接换模型。好模型只为成功找方法，不东绕西绕。
  • 同一份内容、同一份上下文，只换模型，PPT 质量差别明显。
  • 自购 API（以 DeepSeek 为例）：deepseek.com → API 开放平台 → 注册并实名 → 自定义金额充值（课堂充 1 元体验）→ 创建 API Key 并单独保存（等同账户密码）→ WorkBuddy 模型 → 配置自定义模型 → 供应商选“深度求索” → 粘贴 Key 保存 → 选 V4 Flash，不选 V4 Pro。
  • 讲师实测 1 元：问答类大约能用一周，复杂任务可能 10 秒就用完。
8. 工作空间与三栏界面
  • 工作空间（现在叫“分组”）本质是一个本地文件夹，输入和输出都在里面。可以新建分组，也可以直接打开已有文件夹。
  • 个人空间是铁打的，智能体是流水的，上下文才是核心竞争力。
  • 三栏：左边找任务，中间提要求，右边看成果。
  • 文件上的常用操作：打开文件夹、用默认应用打开、添加到对话框（重点引用）、复制路径（跨智能体引用绝对路径）、上传到云端（手机微信小程序接力）、分享链接（同事共享）。
  • 左栏：常用任务置顶；重要对话一定要重命名，默认名是第一句话，过几天就找不到了。
9. 权限与文件安全
  • “允许完全访问”有三个开关：文件操作、终端命令、上网与外发（公司信息安全最敏感的一项）。
  • 打开等于自动驾驶，派完活可以走开；关闭等于辅助驾驶，大事小事都要请示。
  • 打开后整台电脑都是它的工作空间。隐秘文件建议关掉相应权限或换一台电脑，按自己的业务情况权衡。
  • 动文件前先复制一份，原文件保留，别让工作文件夹成为唯一副本，改了就回不来。
10. 资料库、腾讯文档、IMA
  • 本地文件：临时上下文，拖进对话框或 Ctrl+V 即可。
  • 资料库：上传后在云端，人和 AI 都能改（人机双写）。AI 做到 99%，最后 1% 人来改只要 1 秒。适合放长期常用的工艺参数、方法论。
  • 腾讯文档：核心价值是多人协同，跨部门项目在同一份文档里各自维护。
  • IMA（ima.qq.com）：放公司以外、不涉密的公共知识。共享知识库能让部门里一位高手的积累全员可用；单账号容量有限，可多账号挂到共享库扩容。
11. 浏览器操控与数据导入
  • 设置 → 智能体 → 浏览器，按提示安装，并给浏览器添加扩展程序。装好后 AI 能替你打开网站、填表、注册登录，验证码由你输入。
  • 适用于内网系统填单、工单录入、电商上架这类字段多、规则清楚的活：下班前派活，第二天早上验收。
  • 数据导入：换新电脑第一件事是迁移数据。也可以把其他 AI 产品的历史对话导进来，防止账号出问题后丢失。数据比电脑值钱。
12. Plan 模式与打断
  • 三种模式：Ask 先问（只问答），Plan 先规划（确认后执行），默认模式直接执行。
  • 默认模式适合目标清楚、范围明确、快速修改。Plan 适合任务复杂多步骤、边界模糊要反复澄清、需要拆步骤和定验收标准、需要多次确认范围。
  • 计划五要素：目标、步骤、依赖、改动、验收。
  • 流程：AI 反问澄清 → 出计划 → 人评审 → 把修改意见告诉 AI → 改成可执行计划 → 执行。这和软件开发先做架构设计、生产先做计划分解是一个道理。
  • 硬打断：发现它在胡说，直接终止任务再发新指令。软打断：等它干完这件再做下一件。
13. 技能 Skill
  • 技能的本质是流程加知识。流程同行之间差不多，真正不可替代的是私有知识库。
  • 讲师案例：做课程大纲，从多轮对话约 2 小时，变成调用技能约 20 秒出稿，客户直接认可。
  • 安装：专家技能连接器 → 技能 → 搜索 → 选下载量最大的。今天装的三个：去AI味（humanizer）、数据分析（Data Analysis）、PPT Master。
  • 沉淀什么知识：选经过验证、拿到业绩、市场认可的，而不是还没验证的想法。AI 的原理是“抄答案”，考什么题就准备什么答案。
  • 怎么自己做技能，见“做专家与做技能”。
14. 顺手的小技巧
  • 语音输入：讲师全程用豆包输入法（认准官方下载）。说话的速度大约是打字的 3 倍。
  • 怎么对待下属，就怎么对待 AI：标准讲清楚，做不好就施压，要求它按系统框架回答。
  • 重要对话重命名，常用任务置顶。
