1第一步：PRD + Spec 标准 → 生成 Workspace

模式固定为 new：只做初始化，不开发业务代码，不安装业务依赖，不发布站点。

  1. 把两份材料一起放进对话

    上传 IPO Word（或粘贴正文），并解压标准包、把 spec-workspace-standard-v2.0/ 文件夹放进项目目录。工具只能读对话附件时，就把 AGENTS.md 与 .agents/skills/spec-workspace-init/SKILL.md 一起贴进对话，其余文件按提示词要求按需读取。

  2. 复制下面这段提示词，原样发出去

    这段提示词已经把七件容易漏的事写死：读什么、分哪三类资料、要写哪些规格、缺口怎么分级、交付什么、怎么校验、不许说什么。不要精简它。

  3. 看它交付的 HTML 摘要，不看它说了什么好听的话

    合格产出必须有：十份规格无空章、需求有编号与来源、缺口分三级、ZIP 与 HTML 同名同版本、状态为 BASELINE_DRAFT、业务测试为 NOT_RUN。

第一步 · 生成 Workspace 初始化输入包约 900 字 
请把我提供的 PRD（或 IPO）与《Spec Workspace 初始化标准 v2.0》一起处理，生成本项目专属的 Workspace 初始化输入包。
先读取标准包的 AGENTS.md 和 .agents/skills/spec-workspace-init/SKILL.md，再按需读取 references/ 与 templates/。此次模式为 new；第一步只做初始化，不开发业务代码，不安装业务依赖，不发布站点。

1. 列出实际读到的资料、版本、范围和未能读取的内容；区分我的业务资料、标准模板与课堂示例。不要把示例内容当成我的需求，也不要重复问已有答案。
2. 根据 PRD 生成完整的项目规格：业务目标与边界、IPO、SOP、业务规则与状态机、数据与导入映射、架构与接口候选、页面与输出、权限安全、验收用例和需求追踪。每条关键需求有来源、规则和可检查的预期。
3. 参考初始化 Skill 的“目录初始化—只读盘点—基线候选—评审确认”。有存量代码时仅扫描我明确提供的目录，说明覆盖和遗漏；没有代码时 observed components 为空，把拟建模块放在设计候选里，不编造仓库、组件或已运行结果。
4. 保留已确认企业规范；缺少的技术栈、品牌、接口与权限能力写成设计建议或待确认。非关键缺口不妨碍交付候选包；会改变范围、金额、权限或对外动作的缺口列为阻断，不能靠默认值绕过。
5. 按 templates/workspace 的交付契约，写出实质内容，不只复制空目录或占位符。复制后续所需的 Skill、规范和 tools/workspace_pack.py，使输出包无需原标准包也能继续使用。初始化状态为 BASELINE_DRAFT；业务测试均为 NOT_RUN，除非本轮确实执行且留有证据。
6. 执行结构校验后，生成 outputs 下同版本的《项目名_Workspace_v1.0.0_r001.zip》和《项目名_Workspace_v1.0.0_r001.html》（工具采用英文 project_id 文件名也可以）。只分发获准材料，不包含密钥、本机配置、构建缓存或无关原始文件。
7. 同时告诉我：已初始化什么、仍有哪些关键问题、下一步先确认哪份基线。不得把已打包写成已批准、已开发或已上线。不要自动进入第二步。
项目名可从 PRD 提取；只有无法可靠确定时使用中性的临时项目名并注明。此次资料不足时仍交付有缺口标记的候选包。

复制后粘贴到你的 AI 工具，不需要再补任何说明。如果工具读不到 ZIP，就先解压、把文件夹放进项目根目录再发。

2第二步：基于上一步输出，生成工作台

上一步的十条规格就是这一轮的输入。这一轮不再讨论需求，只把规格变成能点的界面。

  1. 打开上一步的 Workspace 目录

    在同一个对话里继续，或新开对话并把 Workspace 文件夹放进项目根目录。让工具先读 WORKSPACE.md、specs/04-rules.md、specs/07-ui.md、specs/08-security.md。

  2. 在输入框选中专家「工作台搭建师」

    入口在对话框的专家／插件区：搜索「工作台搭建师」→ 选中 → 再发送提示词。同一轮只选一个专家，避免两套方法论互相打架。选中后左下角会显示当前专家名。

  3. 发这句话就行

    需求已经在规格里，不需要再把背景讲一遍。要补的是边界：不编字段、不越权、不发布。

第二步 · 生成工作台（配合专家：工作台搭建师）复制后直接发 
基于上一步输出的 Workspace 初始化包，生成这个项目的工作台界面。先读 WORKSPACE.md、specs/04-rules.md、specs/07-ui.md、specs/08-security.md、specs/09-acceptance.md，再动手。

1. 页面按 specs/07-ui.md 的清单做（导入、判读、导出三页），不要自行增加规格里没有的页面和字段；规格缺失的字段标“待确认”，不要编造。
2. 字段、三态判读、状态流转严格对齐 specs/04-rules.md；规则没写清的，列出来问我，不要用默认值补齐。
3. 权限按 specs/08-security.md 的矩阵实现：默认拒绝，越权动作连入口都不出现，并在页面上提示无权限。
4. 用包内样例数据把主流程跑通，验收用例逐条给可点路径；未执行的标 NOT_RUN，不写“预计通过”。
5. 输出本地可预览版本即可：不发布站点、不接真实数据、不写入任何生产环境。做完告诉我：做了什么页面、哪些规则没落地、下一步该确认哪条缺口。

第二步的合格判据

检查点说明
页面与规格一致页面上每个字段都能在 specs/05-data.md 找到；每个按钮都能在 specs/03-sop.md 找到对应动作
规则可验证缺数据时确实显示「无法判断」，而不是给个看起来合理的数字
权限真的拦换个角色账号，导出／删除入口消失或报无权限
不越界没有出现配方比例、客户真实名称，也没有自动发布链接
表述准确「已做页面」和「已验证通过」分开说，未跑的测试仍是 NOT_RUN
别让它顺手把规格改了。工作台阶段发现规格写错，正确做法是回第一步改 specs/ 并记一条 ADR，而不是在前端代码里悄悄加一条业务逻辑——那样下一个人就再也对不上了。

3练习验收清单

勾选记录存在你自己的浏览器里，不上传。全部勾上才算这轮练习完成0 / 10

  • 下载了两份材料，并确认 IPO 里的 6 组样品数据是课堂模拟、不是真实配方

  • 缺口分了 BLOCKER／NON-BLOCKER／WATCH，并写清影响哪条需求
  • 交付的是 ZIP ＋ HTML 一对，同名同版本，HTML 里有「已初始化／关键缺口／下一步」

  • 第二步前已选中专家「工作台搭建师」，且只选了一个专家
  • 工作台页面的字段与按钮能逐条对回规格，无自造字段
  • 能清楚说出：已初始化什么、还缺什么、下一步先确认哪份基线

4五个最常见的坑

坑会发生什么怎么改
把课堂示例当需求规格里出现示例中的阈值、角色和编号，后面全部返工引用示例时标注「来源：示例（非需求）」，只借格式不借内容
把「文件生成了」当「已批准」直接进开发，做到一半发现范围没定，无法收敛先读 HTML 的「关键缺口」，BLOCKER 不回答就不进开发
所有缺口都写「待确认」没法判断哪个能继续、哪个必须停强制分级：改范围／金额／权限／对外动作的一律 BLOCKER
跳步直接让它写系统没有状态机与权限矩阵，代码里的规则只能靠猜回到第一步，先出规格；第二步再谈界面
编造证据「测试已通过」「接口已联调」查不到记录，交付即失效没跑就写 NOT_RUN，并在 evidence/ 里留位置
