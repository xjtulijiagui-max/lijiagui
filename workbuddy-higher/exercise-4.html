WorkBuddy 工作台搭建：三步就够了

不要一开始就写代码。先把业务需求整理成“定制工作包”，再交给 WorkBuddy 真正搭建，最后持续试用、哪里不对改哪里。需要长期数据、多人权限或 API 时，要明确采用前后端分离；完成后别忘了执行“发布”动作。
STEP 01业务需求 → 定制工作包IPO 最好；没有 IPO 就用业务需求描述 + 标准输出包。
STEP 02定制工作包 → 工作台把定制包交给 WorkBuddy，直接开发、运行、测试。
STEP 03试用 → 修改 → 发布哪里不对改哪里；跑通后发布为可访问站点。

练习任务

你的目标

用下面提供的模拟业务需求和数据，做出一个“销售线索跟进工作台”。重点不是做得复杂，而是完整走通三步流程。

最终结果

至少完成：上传数据 → 展示列表 → 修改一条线索 → 首页统计 → 导出 → 发布站点。

记忆口诀： 需求/IPO + 标准包 → 定制工作包 → WorkBuddy 搭建 → 试用修改 → 发布。

Step 1｜先生成“我的定制工作包”

先下载“工作台搭建输入标准模板.zip”。把业务需求、IPO（如果有）和这个标准输出包一起交给 AI。第一步不是直接做网页，而是先生成属于当前业务的定制工作包。

Step 2｜把定制工作包交给 WorkBuddy 搭建

把 Step 1 生成的定制工作包设为工作空间，然后复制下面提示词。重点是“直接开发、运行和测试”，不要只输出设计说明。

前后端提醒： 如果涉及多人协同、登录权限、数据库长期保存、API、复杂计算或企业系统对接，请明确要求“前后端分离”。前端做页面，后端做逻辑和数据，密钥不能放在前端。

Step 3｜持续迭代：哪里不对就改哪里

不需要重新写一大段 PRD。学员直接用自然语言说问题，WorkBuddy 按问题局部修改，并重新测试相关功能。

最后一步｜一定要做“发布”动作

代码做完不等于别人能访问。确认试跑通过后，再要求 WorkBuddy 执行发布/部署/分享站点动作。
