# 课程大纲模板结构详解

本文件详细说明课程大纲的7大板块结构，供生成定制大纲时参照。

## 总体结构概览

```
┌─────────────────────────────────────┐
│  ① 标题 + 副标题                      │
├─────────────────────────────────────┤
│  ② 课程基本信息（表格）                │
├─────────────────────────────────────┤
│  ③ 学习目标（5-6条 bullet）           │
├─────────────────────────────────────┤
│  ④ 课程模块结构（核心，多张表格）       │
│     ├─ 开场导入                       │
│     ├─ 模块一 ~ 模块六                │
│     │    └─ 每模块含 2-5 个主题       │
│     └─ 课堂问答（收束）                │
├─────────────────────────────────────┤
│  ⑤ 讲师演示说明（可选）                │
├─────────────────────────────────────┤
│  ⑥ 课程特色（4-5条 bullet）           │
├─────────────────────────────────────┤
│  ⑦ 版本组合说明（表格）                │
└─────────────────────────────────────┘
```

---

## ① 标题 + 副标题

**格式**：
- 第1行：课程名称（加粗，大字号，居中）
- 第2行：副标题（斜体，前面加 `——`）
- 第3行：版本标签（空格分隔的大字，如"课 程 大 纲 （一天版 · 面授课）"）

**示例**：
```
**平安AI场景创新工作坊**

*——重塑业务价值 · 从"找AI点子"升级为持续产出高价值场景的经营机制*

课 程 大 纲 （一天版 · 面授课）
```

**设计逻辑**：标题 = 品牌/主题名，副标题 = 一句话核心价值主张。

---

## ② 课程基本信息

**格式**：4行2列的表格（实际渲染为标签+值的配对），共6个字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| 【课程名称】 | 课程全名 | 平安AI场景创新工作坊 |
| 【课程时长】 | 总时长+学时数 | 1天（共约7学时） |
| 【课程对象】 | 目标学员描述 | 各专业公司业务负责人、CTO、业务骨干 |
| 【授课形式】 | 教学方式 | 讲授 + 案例拆解 + 讲师AI演示 + 课堂问答 |
| 【课程主线】 | 课程逻辑主线 | 四段式闭环：识别 → 筛选 → 验证 → 复制 |
| 【课程说明】 | 补充说明 | 1天面授课以讲授+演示为主，无分组产出 |

**设计逻辑**：让决策者一眼看清"给谁上、多长、怎么上、讲什么逻辑"。

---

## ③ 学习目标

**格式**：5-6条 bullet，以 `·` 开头。

**句式规范**：
- 用"理解……""掌握……""了解……""学会……"开头
- 每条聚焦一个能力点
- 从认知 → 方法 → 实践 → 组织 递进

**示例**：
```
· 理解AI场景的本质——业务链条重构，掌握高价值场景判断标准
· 掌握六类场景识别工具（T1–T6），能从流程/知识/业务/技术断点中系统识别AI机会
· 掌握四关漏斗筛选逻辑，将候选机会转化为资源配置决策
· 理解POC→MVP→Pilot→ROI递进验证机制
· 了解三类资产化复制路径
· 理解AI推广组织机制，明确各自角色职责
```

**设计逻辑**：学习目标 = 课程模块的"预告片"，每条对应1-2个模块。

---

## ④ 课程模块结构（核心）

这是大纲的主体，占篇幅70%以上。由若干张表格组成，每张表格对应一个时间块。

### 模块类型

| 类型 | 标识 | 说明 |
|------|------|------|
| 开场 | `opening` | 开营/导入/破冰，通常20分钟 |
| 正式模块 | `module` | 模块一 ~ 模块六，核心内容 |
| 问答收束 | `qa` | 课堂问答/总结，通常15-30分钟 |

### 模块表格结构

每个模块是一张2列表格：
- **第1行（合并）**：模块标题 + 时间段 + 时长
  - 格式：`模块一 认识AI场景创新 09:20–10:30 · 70分钟`
- **后续行**：左列=主题名（加粗），右列=详细内容

### 内容标记系统

详细内容中使用统一标记：

| 标记 | 含义 | 示例 |
|------|------|------|
| `▶` | 主要点（一级） | `▶ AI场景不是"找几个AI点子"` |
| `—` | 子要点/细节/案例 | `— 自动化率82.6%，平均理赔时效7.2分钟` |
| `📺` | 讲师演示环节 | `📺 讲师演示一 机会表生成（15分钟）` |
| `🔧` | 工具/方法环节 | `🔧 T1 流程挖掘` |

### 时间分配参考

**1天版（约7学时，09:00-17:30）**：

| 时间段 | 内容 | 时长 |
|--------|------|------|
| 09:00–09:20 | 开场导入 | 20min |
| 09:20–10:30 | 模块一 | 70min |
| 10:30–12:00 | 模块二 | 90min |
| — | 午休 | — |
| 13:00–14:30 | 模块三 | 90min |
| 14:45–15:45 | 模块四 | 60min |
| 15:55–16:45 | 模块五 | 50min |
| 16:45–17:15 | 模块六 | 30min |
| 17:15–17:30 | 问答收束 | 15min |

**半天版（约3.5学时）**：选3个核心模块，去掉演示环节。

**2天版（约14学时）**：第1天同1天版，第2天增加共创练习+成果汇报。

### 模块内容设计原则

1. **递进性**：模块之间有逻辑递进（认知→方法→实践→复制）
2. **独立性**：每个模块自身完整，有明确的学习产出
3. **密度**：每模块2-5个主题，每主题3-5个 ▶ 要点
4. **案例驱动**：至少1-2个具体案例支撑抽象方法
5. **可操作性**：方法要具体到步骤/工具/模板，不要停留在概念

## ⑤ 讲师演示说明（可选）

**格式**：bullet 列表，说明课程中包含的演示环节。

**适用场景**：面授课/工作坊通常有。纯讲授课或线上课可能没有。

**示例**：
```
· 本课程包含4次讲师AI现场演示，贯穿识别、筛选、验证三个阶段
· 演示一（机会表生成）：现场用AI生成标准机会表
· 演示二（场景判断辨析）：用10个典型场景现场演示判断
```

如果没有演示环节，此板块省略（JSON 中 `demo_notes` 传空数组）。

---

## ⑥ 课程特色

**格式**：4-5条 bullet，以 `·` 开头。

**设计逻辑**：回答"为什么选这门课而不是别家的"。每条突出一个差异化优势。

**常见角度**：
- 案例深度（行业专属案例拆解）
- 方法论体系（自创框架/模型）
- 授课形式（演示/共创/实操）
- 内容密度（高密度/短时间全覆盖）
- 可扩展性（对接其他版本/后续服务）

---

## ⑦ 版本组合说明

**格式**：3列表格（方案/内容描述/建议时长），通常3行。

**设计逻辑**：给决策者提供选择空间——当前版本标★，其他版本作为升级/降级选项。

**示例**：
```
| 方案 | 内容描述 | 建议时长 |
| 方法论认知版（1天）★ | 六模块完整方法论+演示+问答 | 1天（★本版本）|
| 研讨落地版（2天） | 增加3轮共创练习+成果汇报 | 2天 |
| 场景快速共识版（半天）| 精简为核心模块+1次演示 | 半天 |
```

末尾加备注：`*备注：如需其他时间版本，可根据具体内容另行适配输出。*`

---

## 格式细节备忘

- 标点：中文场景用中文标点（`·` `——` `▶` `—`）
- 时间格式：`09:20–10:30 · 70分钟`（用 `–` 不是 `-`）
- 序号：模块用中文数字（一、二、三），子内容用 `▶`
- 加粗：模块标题、主题名、关键字段标签加粗
- 表格：无表头行或表头行留空，直接从内容开始
