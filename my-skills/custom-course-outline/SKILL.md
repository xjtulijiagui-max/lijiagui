# 定制课程大纲生成器

## 这个 skill 做什么

把「客户需求」+「课程大纲模板」→ 输出一份格式专业、内容定制的 Word 课程大纲。

典型场景：客户发来一段需求（可能是录音转文字、需求文档、微信聊天记录），你需要基于自己过去的通用课程大纲模板，快速产出一份针对该客户定制的课程大纲 Word 文档。

## 核心工作流程（6步）

### 第1步：确认输入

需要两样东西：

1. **客户需求** — 以下任一形式：
   - 直接粘贴的文本（录音转文字、需求描述）
   - 文件路径（txt / docx / md）

2. **模板** — 默认使用内置模板（见 `references/template-structure.md`）。
   如果用户指定了其他模板文件，先读取该文件解析其结构。

如果用户只给了需求没提模板，直接用内置模板，不要追问。

### 第2步：分析客户需求

从客户需求中提取以下关键信息（缺什么补什么，不要因为缺一项就停下来问）：

| 提取项 | 说明 | 示例 |
|--------|------|------|
| **行业/公司** | 客户所在行业、公司名 | 保险、银行、制造业、某集团 |
| **课程主题** | 客户想培训什么 | AI场景创新、数字化转型、智能客服 |
| **目标学员** | 谁来上课 | 业务骨干、管理者、CTO、全员 |
| **课程时长** | 半天/一天/两天 | 1天面授、2天研讨 |
| **核心痛点** | 客户想解决什么问题 | "找不到AI落地场景""效率低""不会用AI" |
| **特殊要求** | 客户额外强调的点 | 要有行业案例、要实操、要分组产出 |
| **授课形式** | 面授/线上/工作坊 | 面授+演示、研讨+共创 |

需求文本通常是非结构化的（特别是录音转文字），需要你主动归纳。如果录音转文字里信息不全，基于行业常识合理推断，不要逐条追问。

### 第3步：映射到模板结构

内置模板有7个固定板块（详见 `references/template-structure.md`）：

```
① 标题 + 副标题
② 课程基本信息（表格：名称/时长/对象/形式/主线/说明）
③ 学习目标（5-6条 bullet）
④ 课程模块结构（核心，4-6个模块，每个模块含若干主题）
⑤ 讲师演示说明（可选，面授课通常有）
⑥ 课程特色（4-5条 bullet）
⑦ 版本组合说明（表格：不同时长版本对比）
```

映射规则：
- **标题**：从客户主题提炼，格式为"[客户行业/公司] + [主题] + 工作坊/课程"
- **副标题**：一句话点明课程核心价值主张
- **基本信息**：直接填入第2步提取的信息
- **学习目标**：基于课程主题，生成5-6条"理解/掌握/了解"句式的目标
- **模块结构**：这是最核心的部分，需要根据客户主题设计4-6个递进模块
- **课程特色**：基于客户行业和主题，提炼4-5个差异化亮点
- **版本组合**：通常生成3个版本（半天/1天/2天）

### 第4步：设计课程模块（最关键）

模块设计遵循以下原则：

**递进逻辑**：模块之间必须有清晰的递进关系，不能是平行罗列。
常见递进模式：
- 认知 → 方法 → 实践 → 复制（创新类课程）
- 基础 → 进阶 → 高级 → 综合（技能类课程）
- 现状 → 问题 → 方案 → 落地（转型类课程）

**时间分配**：模块时长加起来要等于总课时。
- 1天课（约7学时）：5-6个模块 + 开场 + 问答
- 半天课（约3.5学时）：3个模块 + 开场
- 2天课（约14学时）：6-8个模块 + 共创练习环节

**每个模块的内容密度**：
- 每个模块2-5个主题（子内容）
- 每个主题用 ▶ 标记分条展开
- 内容要具体到可讲、可演示，不要空洞口号

**案例使用**：尽量使用客户所在行业的案例。如果客户行业没有现成案例，用相邻行业案例并说明可迁移性。

### 第5步：组装内容为 JSON

将所有生成的内容组装成以下 JSON 结构，传递给生成脚本：

```json
{
  "title": "课程标题",
  "tagline": "——副标题",
  "version_label": "课 程 大 纲 （一天版 · 面授课）",
  "basic_info": {
    "course_name": "课程名称",
    "duration": "1天（共约7学时）",
    "audience": "课程对象描述",
    "format": "讲授 + 案例拆解 + 讲师演示 + 课堂问答",
    "main_line": "课程主线描述",
    "description": "课程说明"
  },
  "learning_objectives": [
    "理解……",
    "掌握……",
    "了解……"
  ],
  "modules": [
    {
      "type": "opening",
      "header": "开营 开场导入",
      "time": "09:00–09:20 · 20分钟",
      "topics": [
        {"name": "开场说明", "content": "▶ 要点1\n▶ 要点2"}
      ]
    },
    {
      "type": "module",
      "header": "模块一 模块标题",
      "time": "09:20–10:30 · 70分钟",
      "topics": [
        {"name": "主题名", "content": "▶ 要点1\n— 细节\n▶ 要点2"},
        {"name": "另一主题", "content": "▶ 要点"}
      ]
    },
    {
      "type": "qa",
      "header": "课堂问答",
      "time": "17:15–17:30 · 15分钟",
      "topics": [
        {"name": "关键问答", "content": "▶ Q1：……\n— 回答要点\n▶ Q2：……"}
      ]
    }
  ],
  "demo_notes": [
    "演示说明1",
    "演示说明2"
  ],
  "features": [
    "特色1",
    "特色2"
  ],
  "versions": [
    {"name": "版本名（时长）", "description": "版本描述", "duration": "时长"},
    {"name": "另一版本", "description": "描述", "duration": "时长"}
  ]
}
```

**JSON 格式要点**：
- `content` 字段中用 `\n` 换行，用 `▶ ` 开头表示分条，用 `— ` 开头表示子要点
- `modules` 数组中 `type` 可选值：`opening`（开场）、`module`（正式模块）、`qa`（问答收束）
- `demo_notes` 如果课程没有演示环节，传空数组 `[]`
- `versions` 至少包含当前版本和1-2个其他版本
- **重要**：`content` 字段内不要使用 ASCII 双引号 `"`，会破坏 JSON 解析。需要引用时用中文引号 `「」` 或 `""`（Unicode弯引号）

### 第6步：生成 Word 文档

使用内置脚本生成 Word：

```bash
"C:\Users\xjtul\AppData\Local\Programs\Python\Python312\python.exe" \
  "[skill_dir]/scripts/generate_outline_docx.py" \
  --input "[json文件路径]" \
  --output "[输出docx路径]"
```

操作步骤：
1. 将第5步的 JSON 写入临时文件（如 `C:\Users\xjtul\AppData\Local\Temp\opencode\outline_data.json`）
2. 运行脚本，指定 output 路径（通常保存到桌面或用户指定位置）
3. 文件名格式：`[课程名]_课程大纲_[版本]_[形式].docx`

**中文路径注意**：PowerShell 对中文路径有问题。JSON 文件路径和输出路径都用绝对路径，脚本内部用 Python 处理编码。

## 内容质量标准

生成的内容必须达到以下标准：

### 信息密度
- 每个主题至少3个 ▶ 要点
- 每个要点要有具体内容，不要只有标题没有展开
- 案例要有数据（如有），不要泛泛而谈

### 专业性
- 使用行业术语但不堆砌
- 方法论要有框架感（编号体系、分类逻辑）
- 避免培训行业陈词滥调（"赋能""抓手""闭环"等过度使用）

### 可交付性
- 学员或决策者拿到大纲能理解课程讲什么
- 时间安排合理，不要出现某个模块2小时、另一个10分钟
- 模块之间的过渡自然

## 特殊情况处理

### 客户需求非常简短
如果客户只说了一句话（如"我们银行想搞个AI培训"），基于行业常识补全：
- 银行 → 合规要求高、数据敏感、客户服务场景多
- 制造业 → 供应链、质检、设备维护场景
- 保险 → 核保、理赔、客服、续期场景

补全后在输出中说明"基于行业常识推断，建议与客户确认"。

### 客户要求特定时长但模板是1天版
调整模块数量和时间分配：
- 半天版：压缩到3个核心模块，去掉演示和共创
- 2天版：在第1天基础上增加共创练习和成果汇报
- 在版本组合说明中列出所有版本

### 客户要求特定格式（不是Word）
本 skill 默认输出 Word。如果客户要 PPT，提示用户使用 pptx skill。
如果要飞书文档，提示使用 lark-doc skill。
