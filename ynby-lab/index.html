02

先立规矩：目录＋权限

PPT 第 8、17、26 页

三条红线（课堂必讲）

  • 数据红线：不上传密钥、身份证件、薪酬明细、患者/经销商敏感资料；只用模拟或脱敏副本。
  • 权限红线：最小必要授权；只读练习材料、只写 output，不接未经批准的外部系统。
  • 动作红线：外发、审批、付款、删除、覆盖原件、制度定稿，必须人工确认，课堂一律不做。

目录结构与权限四分法

  • 01-原始副本 只读：脱敏样本、制度摘录、模板
  • 02-过程文件 可写：解析结果、字段映射、异常清单
  • output 可写：最终草稿、验收表、风险清单
  • 读 / 写 / 外发 / 执行 四类动作分别授权，不打包授权
提示词 0｜环境初始化（建目录 + 操作边界 + 权限待办） 建目录可以交给 AI，开权限不能 
先出计划，不执行。

【任务】在当前工作区建立 AI 练习目录，并生成一份《00-操作边界.md》。

【要建的目录】已存在的只补缺失项，不清空、不覆盖、不删除任何文件。

云南白药AI练习工作区/
├─ 01-原始副本/          ← 只读：授权脱敏样本、制度摘录、模板
│  ├─ 01-数据与流程/ 02-行政/ 03-风控/ 04-财务/ 05-人力/ 06-党群/
├─ 02-过程文件/          ← 可写：解析结果、字段映射、执行计划、异常清单
└─ output/               ← 可写：最终草稿、验收表、风险清单

【要生成的文件】00-操作边界.md，写明五件事：
1. 可读范围：仅 01-原始副本
2. 可写范围：仅 02-过程文件 与 output
3. 禁止动作：覆盖或删除原件、外发、代审批、付款、定稿、上传含个人信息/薪酬/密钥的材料
4. 命名规则：部门_任务_日期_v01（例：财务_四方核对_20261127_v01）
5. 每次开工前先读本文件；与我口头要求冲突时，停下来问，不要自行选择

【要输出给我本人的清单】"权限设置待办"，逐条列出我需要在 WorkBuddy 权限设置里自行开启或关闭的项：
- 读本地文件：仅限本工作区
- 写文件：仅限 output 与 02-过程文件
- 联网 / 外部系统：本次关闭
- 外发 / 消息：关闭
并明确写一句：你不判断我已开还是已关，只列清单让我自己点。

【红线】在我确认计划前，不要创建任何目录或文件；若同名文件已存在，停下来告诉我，不要覆盖。
一个必须分清的地方：建目录是写文件动作，AI 能自己完成；「最小权限」的读、写、外发开关在 WorkBuddy 权限设置里，属于系统能力。提示词只能约束 AI 自觉遵守，不能替你打开或关闭权限。所以这段提示词让它输出一份待办清单给你本人去点，而不是替你宣称「权限已设置」。
03

通用提示词与验收六项

PPT 第 28、33 页
通用提示词｜从岗位经验到结构化任务（四层结构） 任何部门、任何任务都能套，把方括号换成你的 
【角色与资料】你是【岗位】。只读【授权副本 / 制度版本 / 模板】；材料不足先列缺口再问我，不要猜。

【任务与规则】完成【具体任务】。按【步骤 / 口径 / 字段 / 例外】执行；区分「事实」与「推断」，推断必须标「待核实」。

【交付与验收】输出【文件类型 + 模板】到 output/，文件名用【部门_任务_日期_v01】；附【来源索引】与【待确认清单】；验收人是【岗位】。

【红线与兜底】不覆盖原件、不外发、不代审批、不付款、不定稿；缺数据、规则冲突、权限不足时暂停并说明，不要硬做。
验收项要看什么不合格怎么办
能打开文件实测可打开，不是「生成成功」的提示在原任务里追问具体问题，保留旧版；缺资料列缺口，禁止自行猜测或强行交付。
内容对事实、数字、日期、人员、制度版本、结论边界
格式对字段、模板、标题、图表、页码
范围对只处理指定材料，没有顺手改别的文件
可追溯关键数据有来源、口径、行号或页码
可交付可编辑、路径正确、版本明确（v01/v02）

四道人工关口

PPT 第 82 页：AI 做初稿，人做终审
关口人必须确认的课堂上的对应动作
① 输入关材料范围、脱敏程度、制度版本、授权状态；禁止真实敏感资料越权只下本部门那 2—3 个文件；确认它们是模拟数据
② 处理关清洗与计算规则、异常标记是否合理；保留原始记录，不擅自修改核对行数平衡、单位换算只做一次、重复项未静默删除
③ 输出关数字、日期、人员、来源、格式、风险结论；不合格退回修订用第 06 节清单逐项打勾，不合格的当场退回重跑
④ 发布关授权人确认外发、审批、付款、删除、覆盖、定稿；保留日志与版本课堂一律不外发、不审批、不付款
05

IPO 与课堂节奏

PPT 第 55、56、61 页

I｜Input 输入

给 AI 什么？授权文件、结构化数据、业务标准、历史案例与样例。资料缺失先追问，不要让它猜。

P｜Process 处理

按什么逻辑执行？步骤、判断规则、优先级、例外与人工确认关口。把人的经验变成可写下来的规则。

O｜Output 输出

交什么成果？Word、Excel、PPT、清单或报告；明确字段、结构、模板与质量标准。

边界与验收：信息不足先追问再降级；不得编造制度、数据与人员结论；交付物必须可验收——「看起来不错」不是验收标准。
环节用时做什么
进场5 分钟打开本部门练习页，下载 2—3 个数据文件，放进 01-原始副本
读场景5 分钟看 01 节三个场景，判断哪一个是本周真的会发生的任务
跑任务20 分钟贴提示词 → 先看计划 → 执行 → 打开输出逐项核对
验收10 分钟按 06 节清单勾选；至少退回重跑一次，体验「不合格怎么办」
