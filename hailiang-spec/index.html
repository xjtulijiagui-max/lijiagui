第一步 · 生成 Workspace 初始化输入包直接复制 
请把我提供的 PRD（或 IPO）与《Spec Workspace 初始化标准 v2.0》一起处理，生成本项目专属的 Workspace 初始化输入包。
先读取标准包的 AGENTS.md 和 .agents/skills/spec-workspace-init/SKILL.md，再按需读取 references/ 与 templates/。此次模式为 new；第一步只做初始化，不开发业务代码，不安装业务依赖，不发布站点。

1. 列出实际读到的资料、版本、范围和未能读取的内容；区分我的业务资料、标准模板与课堂示例。不要把示例内容当成我的需求，也不要重复问已有答案。
2. 根据 PRD 生成完整的项目规格：业务目标与边界、IPO、SOP、业务规则与状态机、数据与导入映射、架构与接口候选、页面与输出、权限安全、验收用例和需求追踪。每条关键需求有来源、规则和可检查的预期。
3. 参考初始化 Skill 的“目录初始化—只读盘点—基线候选—评审确认”。有存量代码时仅扫描我明确提供的目录，说明覆盖和遗漏；没有代码时 observed components 为空，把拟建模块放在设计候选里，不编造仓库、组件或已运行结果。
4. 保留已确认企业规范；缺少的技术栈、品牌、接口与权限能力写成设计建议或待确认。非关键缺口不妨碍交付候选包；会改变范围、金额、权限或对外动作的缺口列为阻断，不能靠默认值绕过。
5. 按 templates/workspace 的交付契约，写出实质内容，不只复制空目录或占位符。复制后续所需的 Skill、规范和 tools/workspace_pack.py，使输出包无需原标准包也能继续使用。初始化状态为 BASELINE_DRAFT；业务测试均为 NOT_RUN，除非本轮确实执行且留有证据。
6. 以“海亮智汇后勤校园报修工单跟进”为项目名称；执行结构校验后，生成 outputs 下同版本的《项目名_Workspace_v1.0.0_r001.zip》和《项目名_Workspace_v1.0.0_r001.html》（工具采用英文 project_id 文件名也可以）。只分发获准材料，不包含密钥、本机配置、构建缓存或无关原始文件。
7. 同时告诉我：已初始化什么、仍有哪些关键问题、下一步先确认哪份基线。不得把已打包写成已批准、已开发或已上线。不要自动进入第二步。
项目名可从 PRD 提取；只有无法可靠确定时使用中性的临时项目名并注明。此次资料不足时仍交付有缺口标记的候选包。

第二步 · 生成工作台（配合专家：工作台搭建师）复制后直接发 
基于上一步输出的 Workspace 初始化包，生成这个项目的工作台界面。先读 WORKSPACE.md、specs/04-rules.md、specs/07-ui.md、specs/08-security.md、specs/09-acceptance.md，再动手。

1. 页面按 specs/07-ui.md 的清单做（工单导入、异常核对、跟进结果导出三页）；不增加规格之外的页面或字段，未确认的内容标“待确认”，不要编造。
2. 工单字段、状态冲突、超时风险与人工复核节点严格对齐 specs/04-rules.md；不要把“维修已完成”自动当作“已验收”，规则缺失时列出待确认事项，不使用默认值补齐。
3. 权限按 specs/08-security.md 的矩阵实现：默认拒绝，越权动作连入口都不出现，并在页面上提示无权限。
4. 用包内样例数据把主流程跑通，验收用例逐条给可点路径；未执行的标 NOT_RUN，不写“预计通过”。
5. 只输出基于六条模拟工单的本地可预览版：不发布站点、不接真实系统、不写入任何生产环境。做完告诉我：做了什么页面、哪些规则没落地、下一步该确认哪条缺口。
